## 3. สิ่งที่ทำในรอบวันที่ 26 ส.ค. 2026

1. **`App.tsx` เขียนใหม่ทั้งไฟล์** — นี่คือจุดที่งานรอบก่อนหยุดกลางคัน `AppShell`/`LegacyShell` เขียนเสร็จแล้วแต่ `App.tsx` ยังเป็นโครงเก่า 477 บรรทัด ทำให้ `tsc` พังและแอปเปิดไม่ได้ ตอนนี้เหลือหน้าที่เดียวคือถือ state ระดับแอป (แท็บ ธีม autosave history คีย์ลัด) แล้วเลือก shell ผ่าน `localStorage['vsg:ui']`
2. **คีย์ลัดครบตามที่ `HelpSheet` ประกาศ** — เพิ่ม `Ctrl+1…6` สลับแท็บที่ยังไม่เคยมี (ตรวจแล้วว่าทำงานจริงในเบราว์เซอร์)
3. **แก้ error ที่ค้าง 3 จุด** — `vite-env.d.ts` (`onMaximizeChange` คืน unsubscribe ไม่ใช่ void), `AssetsTab` (import ที่ไม่ได้ใช้), `useExporter` (generic ของ `readStored` แคบเกินจนเทียบค่าไม่ได้)
4. **ลบ `ThemeTab.tsx`** — ไม่มีใคร import แล้วตั้งแต่ `TemplateTab` มาแทน
5. **`ErrorBoundary` เขียน fallback ใหม่** — ใช้ `Btn` + สเกลตัวอักษร token แทนค่าดิบ `text-[13px]` และย้ายรายละเอียดทางเทคนิคไปไว้ใต้ `<details>` · ข้อความทั้ง TH/EN เขียนใหม่ให้คนนอกอ่านรู้เรื่อง (แผนเฟส 5.4)
6. **เป้าคลิก 32px (แผนข้อ 9.7)** — เพิ่มคลาส `.tap-min` ใน `index.css` ที่ขยายพื้นที่กดโดยไม่เปลี่ยนขนาดที่ตาเห็น ใส่ให้ปุ่มไอคอน `size="sm"` ทุกตัวผ่าน `BTN_ICON_ONLY.sm` · ถ่างช่องไฟ undo/redo เป็น 4px กันพื้นที่กดทับกัน · ช่องวันในปฏิทิน `WeekPicker` สูง 32px

14. **ปฏิทินเลือกสัปดาห์เคยขึ้นภาษาปนกัน — แก้แล้ว** · `WeekPicker` อ่านชื่อเดือนจาก `meta.language` ซึ่งเป็นภาษาที่จะ *พิมพ์ลงการ์ด* ผลคือตั้ง UI เป็นอังกฤษแต่ปฏิทินขึ้น "ส.ค. 2026" ปนกลางเมนูอังกฤษ · เปลี่ยนมาอ่าน `uiLanguage` · หัวคอลัมน์วันก็ hardcode `['M','T','W'…]` ไว้ ย้ายไปเป็น `DOW_INITIAL` ใน `data/labels.ts` ที่มีทั้ง ไทย/อังกฤษ
15. **ถอดปุ่ม "คัดลอกจากสัปดาห์ก่อน"** ตามคำสั่ง (ทับแผนข้อ 8.2.5) — action `duplicateLastWeek` ใน store **ไม่ได้ลบ** และคีย์ i18n `duplicateLastWeek` / `duplicatedWeek` / `noPrevWeek` / `uiLangGroup` ก็ยังอยู่ ตอนนี้ไม่มีใครเรียกแล้ว
16. **สวิตช์ภาษาสองอันแยกกันชัด** (ทับแผนข้อ 7.2.4) — เดิมวางแถบ TH/EN สองแถบหน้าตาเหมือนกันเป๊ะติดกันกลางแถบพรีวิว แยกไม่ออกว่าอันไหนเปลี่ยนอะไร

    - **ภาษาการ์ด** → ย้ายไปชิดขวาของแถบพรีวิว อยู่กลุ่มเดียวกับปุ่มเส้นบอกขอบเขตและปุ่มส่งออก มีเส้นคั่นกั้น
17. **บั๊กเลย์เอาต์มือถือค้างบนจอกว้าง — แก้แล้ว** · `AppShell`/`LegacyShell` อ่าน `window.innerWidth` ตอน render แรกครั้งเดียวแล้วรอ event `resize` ถ้าหน้าต่างยังจัดขนาดตัวเองไม่เสร็จตอนสคริปต์รัน จะได้ค่าผิดแล้วค้างอยู่อย่างนั้นจนกว่าผู้ใช้จะลากหน้าต่างเอง (เจอจริงตอนทดสอบ: จอ 1280px แต่ได้แถบแท็บล่างแบบมือถือ) · เขียน `useWideLayout()` ที่ใช้ `matchMedia` + sync ซ้ำใน effect แล้วให้ทั้งสอง shell ใช้ร่วมกัน · โค้ดเดิมยังมีบั๊กลำดับตัวดำเนินการ `cur === window.innerWidth >= 768` ซึ่งอ่านว่า `(cur === window.innerWidth) >= 768` = `false` เสมอ
18. **เก็บคำไทยที่ยังปนอังกฤษ** — `dayEditHint` ("คลิกแถวบน canvas เพื่อเปิด panel วันนั้น" → "คลิกแถววันบนภาพเพื่อเปิดแผงแก้วันนั้น") · `exportAllSizes` · `autosaveNote`

### ฟีเจอร์ใหม่: หมุนภาพ + พลิกภาพตัวละคร (27 ส.ค. 2026)

19. **`ArtTransform` เพิ่ม `rotation?` `flipX?` `flipY?`** — เป็น optional ทั้งหมด draft เก่าไม่มีฟิลด์นี้ ต้องอ่านด้วย `?? 0` / `?? false` เสมอ
20. **`ArtFrameGroup` หมุนรอบจุดกึ่งกลางช่องภาพ** ผ่าน `offsetX/offsetY` = ครึ่งหนึ่งของกล่องภาพ แล้วเลื่อน `x/y` ไปที่จุดกึ่งกลางชดเชย · พลิกด้วย `scaleX/scaleY = -1`
    - **จุดสำคัญ:** เมื่อไม่มีการหมุนหรือพลิกเลย โค้ด**ไม่ส่ง prop ใหม่ลงไปเลย** (ไม่ใช่ส่ง `rotation={0}`) ใช้เส้นทาง `x={artBox.x} y={artBox.y}` แบบเดิมเป๊ะ เพื่อให้งานเก่าเรนเดอร์เหมือนเดิมทุกไบต์
    - เพิ่ม `rotation`/`flipX`/`flipY` เข้า dependency ของ effect ที่ rebuild cache ด้วย ไม่งั้นกดแล้วภาพไม่ขยับ (mask group ถูก cache ไว้)
21. **`AssetsTab` เพิ่มสไลเดอร์หมุน (−180…180°) + ปุ่ม 90° + ปุ่มพลิกซ้ายขวา/บนล่าง** · ปุ่มพลิกเป็น toggle มี `aria-pressed` และเปลี่ยนสีเป็น primary ตอนเปิด · ปุ่ม "พอดีกรอบ" ล้างการหมุนด้วย ไม่งั้นกดแล้วยังเอียงอยู่ · ภาพย่อในแท็บใช้ลำดับ transform เดียวกับ Konva (เลื่อน → ซูม → หมุน → พลิก) ไม่งั้นภาพย่อไม่ตรงกับการ์ดตอนหมุนพร้อมเลื่อน
22. **ตั้งใจไม่ซูมชดเชยอัตโนมัติตอนหมุน** — หมุนแล้วมุมภาพหลุดออกนอกช่องจนเห็นพื้นโปร่งได้ ผู้ใช้ซูมเพิ่มเอง ถ้าซูมให้อัตโนมัติ สไลเดอร์ซูมจะขยับเองโดยผู้ใช้ไม่ได้สั่ง

## 4. ของค้าง

### 4.1 เฟส 0 — hash ตั้งต้นไม่มีและสร้างย้อนหลังไม่ได้ *(ต้องยอมรับความจริง)*

แผนข้อ 1.4 บอกว่า PNG ก่อนและหลัง redesign ต้อง hash ตรงกัน แต่ **ไม่มีใครเก็บ hash "ก่อน" ไว้** และตอนนี้ redesign ทำไปหมดแล้ว จึงพิสูจน์ย้อนหลังไม่ได้ อย่าสร้างไฟล์ `baseline-hashes.txt` ขึ้นมาลอย ๆ แล้วเรียกว่าหลักฐาน — มันจะเป็นหลักฐานปลอม

สิ่งที่ยังทำได้และควรทำ คือเก็บ hash **ตอนนี้** ไว้เป็นหลักกันงานรอบต่อไปทำ output เพี้ยน วิธีที่ให้ค่าคงที่จริง:

1. เปิดแอปตัวจริง (Electron ไม่ใช่เบราว์เซอร์ — ผลเรนเดอร์ต่างกัน)
2. ไปที่ `#/render-test` เพื่อบังคับข้อมูลให้เป็นชุดอ้างอิงที่ตายตัว
3. Export PNG ที่ preset 1080p แล้วเก็บ SHA-256 ลง `docs/baseline-hashes.txt` พร้อมวันที่และเวอร์ชัน Electron
4. รอบถัดไปที่แตะ `components/canvas/**` ให้ทำซ้ำแล้วเทียบ

> ลองเก็บ hash จากในเบราว์เซอร์แล้ว **ใช้ไม่ได้** — `canvas.toDataURL()` ของ preview ผูกกับขนาดหน้าต่างและงบพิกเซลของ `ScheduleStage` ค่าเลยเปลี่ยนทุกครั้งที่ลากหน้าต่าง

### 4.2 แกลเลอรีเทมเพลต 10 ใบ + `thumb.webp` *(งานคอนเทนต์ ไม่ใช่งานโค้ด)*

ตอนนี้มีเทมเพลตเดียวคือ Sakura Diary และ `public/templates/` ยังว่าง `TemplateTab` จึงตกไปใช้ตัวย่อ "SA" แทนภาพย่อ **โครงฝั่งโค้ดรองรับครบแล้ว** — `style` (ตัวกรอง), `thumb` (ภาพย่อ), `controls` (ตัวปรับที่จะโชว์), `tones` (โทนที่แนะนำ) เหลือแค่ผลิตเทมเพลตกับภาพย่อจริง

เวลาทำเทมเพลตใบที่ 2 ให้ใส่ `tones` ด้วย เช่น `"tones": ["sakura", "peach", "lavender"]` แล้วปุ่ม "ดูโทนสีทั้งหมด" จะโผล่ขึ้นมาเอง

## 5. ข้อสังเกตที่ตัดสินใจไว้แล้ว อย่ากลับมาแก้โดยไม่คุยกัน

0. **ข้อห้าม "ห้ามแตะไฟล์" ถูกผ่อนเป็น "เพิ่มของใหม่ได้"** (เจ้าของงานตัดสินใจ 26 ส.ค. 2026) — `src/main/**`, `src/preload/**`, `store/**`, `export/**` เพิ่มฟิลด์ ฟังก์ชัน หรือ IPC ใหม่ได้ แต่ **ยังห้ามแก้หรือลบของเดิม** เจตนาของข้อห้ามคือกันไม่ให้ logic เดิมเพี้ยน ไม่ใช่กันไม่ให้ต่อยอด
1. **`--control-sm` คงไว้ที่ 28px** ตามแผนข้อ 5.4 ไม่ขยายเป็น 32px เพราะจะดัน titlebar 36px และ HUD ซูมจนอึดอัด เป้าคลิกแก้ด้วย `.tap-min` แทน — ปุ่ม chip โทนสีและปุ่มขึ้น/ลงใน `NumberInput` จึงยังสูง 28px และ 26px อยู่ ซึ่งตั้งใจ
2. **`localStorage['vsg:ui']` ค่าเริ่มต้นคือโครงใหม่** ตั้ง `'v1'` เท่านั้นถึงจะได้ `LegacyShell` (แผนเฟส 3.1 เขียนไว้ว่าเริ่มที่ v1 แต่ตอนนี้โครงใหม่นิ่งแล้วจึงกลับด้าน)
3. **`vsg:theme` ห้ามเปลี่ยนชื่อคีย์** ตามความเสี่ยงข้อ 12.7
4. **ป้ายกำกับ history มาจากการ diff snapshot ไม่ใช่จากชื่อ action** — history ที่นี่ดักจากการที่ store ขยับ ไม่ได้ถูกสั่งด้วยชื่อ ถ้าจะทำให้ป้ายละเอียดขึ้น ให้ไปเพิ่มเงื่อนไขใน `describeChange()` อย่าไปไล่ใส่ชื่อที่ call site ทุกจุดแล้วลืมบางจุด
5. **โทนสีของ `themeStore`/`textStyleStore` ไม่ได้อยู่ใน history** — `ScheduleData` ไม่ครอบสองสโตร์นี้ การเปลี่ยนโทนหรือฟอนต์จึง undo ไม่ได้ ซึ่งเป็นพฤติกรรมเดิม ไม่ใช่ของที่เพิ่งพัง

## 6. ตรวจอะไรบ้างก่อนบอกว่าเสร็จ

คำสั่งที่รันจริงแล้วผ่านในรอบนี้:

```bash
npx tsc -b
```

```bash
npx oxlint
```

```bash
npx vite build
```

ผล: `tsc` ไม่มี error · `vite build` ผ่าน สร้าง `dist/` + `dist-electron/` ครบ · `oxlint` มีแต่ warning ที่มีมาก่อนแล้ว (`only-export-components`, `set-state-in-effect`, และ `dist-electron/` ที่ไม่ควรถูก lint ตั้งแต่แรก)

ตรวจในเบราว์เซอร์แล้วผ่าน:

1. สลับ `vsg:ui` เป็น `v1` แล้วกลับ — ทั้งสองโครงเปิดใช้งานได้ ไม่มี error ใน console
2. `Ctrl+3` ไป Assets · `Ctrl+E` ไป Export — ทำงานจริง
3. ภาษาไทยที่แผงกว้าง 280px ครบทั้ง 6 แท็บ — ไม่มีข้อความล้นกล่อง ไม่มีแถบเลื่อนแนวนอน
4. ช่องวันในปฏิทินวัดได้ 41×32px
5. เปิดครบทั้ง 6 แท็บ ไม่มีแท็บไหนตกลง `ErrorBoundary` และ console สะอาด (ต้องเปิดแท็บเบราว์เซอร์ใหม่ตรวจ — buffer ของ console เก็บ error จาก HMR ระหว่างแก้ไว้ด้วย ทำให้ดูเหมือนพังทั้งที่ไม่พัง)
6. tooltip undo/redo — กด "สัปดาห์ถัดไป" แล้วได้ "เลิกทำ (Ctrl+Z) — เปลี่ยนสัปดาห์" · กด Ctrl+Z แล้วป้ายย้ายไปฝั่ง redo ถูกต้อง
7. โทนสีของเทมเพลต — ทดสอบด้วยการใส่ `tones: ['sakura','peach','lavender']` ลง `layout.default.json` ชั่วคราว ได้ชิป 3 อัน กดปุ่มแล้วเป็น 6 อัน กดกลับได้ **แล้วคืนไฟล์กลับเป็นของเดิมแล้ว**
8. สลับสว่าง/มืด — token สีสลับครบทุกตัว (`canvas` `surface` `ink` `ink-muted` `accent` `line-strong`) และกดกลับแล้วคืนค่าเดิม
9. **คีย์ i18n ครบทั้งสองภาษา** — สคริปต์เทียบแล้ว: interface 263 คีย์ · `en` 263 · `th` 263 · ไม่มีขาด ไม่มีเกิน
10. **แถบเมนู** กว้าง 76px โชว์ชื่อครบ 7 รายการเรียงตามที่สั่ง
11. **กดเมนูระหว่างเปิดแผงแก้วัน** — เปิดแผง "จันทร์ 24 ส.ค." แล้วกด "ทั่วไป" สลับไปแท็บทั่วไปจริง
12. **ปุ่มในปฏิทินทำงานครบ** — ลูกศรถัดไป 24 ส.ค. → 31 ส.ค. · ลูกศรย้อน → 24 ส.ค. · "สัปดาห์นี้" → 24 ส.ค. · "สัปดาห์หน้า" → 31 ส.ค. · คลิกวันที่ 10 ก.ย. → 7–13 ก.ย.
13. **ปฏิทินภาษาเดียวกันทั้งแผง** — ไทยได้ `สัปดาห์ของ · 24 ส.ค. – 30 ส.ค. 2026 · จ อ พ พฤ ศ ส อา` · อังกฤษได้ `WEEK OF · 24 AUG – 30 AUG 2026 · M T W T F S S`

### ข้อจำกัดของการตรวจในเบราว์เซอร์ที่ต้องรู้

**อ่านพิกเซลบน canvas ในหน้าต่างพรีวิวนี้ไม่ได้** — เมื่อ Browser pane ไม่ได้ถูกแสดงผล หน้าเว็บจะไม่ composite เฟรม ทั้ง `toDataURL()` และ `getImageData()` จึงคืนค่าค้างหรือว่างเปล่า ทดสอบแล้ว: ลบภาพตัวละครออกทั้งใบ ค่า hash ของ canvas ก็ยังเท่าเดิม

**วิธีตรวจที่ใช้ได้จริง** คืออ่าน scene graph ของ Konva ตรง ๆ (dev server เสิร์ฟเป็น ES module ตัว instance จึงเป็นตัวเดียวกัน):

```javascript
const K = (await import('/node_modules/.vite/deps/konva.js')).default; K.stages[0].find('Image')
```

ใช้วิธีนี้ยืนยันฟีเจอร์หมุน/พลิกแล้ว: ค่าเริ่มต้น `x=-4 y=0 rot=0 sx=1 sy=1 ox=0 oy=0` · กด 90° ได้ `x=700 y=880 rot=90 ox=704 oy=880` (704×880 = จุดกึ่งกลางช่อง 1408×1760 พอดี) · พลิกซ้ายขวาได้ `sx=-1` · พลิกทั้งสองได้ `sx=-1 sy=-1` · กดรีเซ็ตกลับมาเท่าค่าเริ่มต้นเป๊ะทุกตัว

**ยังไม่ได้ตรวจ — ต้องทำในแอป Electron ตัวจริง เบราว์เซอร์ตรวจแทนไม่ได้**

0. **หน้าตาจริงของภาพที่หมุน/พลิกบนการ์ด** — ยืนยันแล้วแค่ระดับ scene graph ว่าค่าถูกต้อง แต่ยังไม่มีใครเห็นภาพจริง ต้องเปิดแอปแล้วลองหมุนดูว่ามุมภาพหลุดกรอบมากแค่ไหน
1. ลาก / ย่อ / ขยาย / ปิดหน้าต่าง (`-webkit-app-region` ใช้ได้เฉพาะใน Electron)
2. export PNG และ GIF ออกมาเป็นไฟล์จริง
3. **ปุ่ม "เปิดโฟลเดอร์" ที่เพิ่งเพิ่ม** — ในเบราว์เซอร์ `window.api.shell` ไม่มี ปุ่มจึงไม่โผล่เลย ต้อง export จริงหนึ่งครั้งแล้วดูว่ากล่องเส้นทางไฟล์ขึ้น และกดแล้ว File Explorer เปิดค้างที่ไฟล์นั้นจริง
4. โหลด draft เก่าที่บันทึกไว้ก่อน redesign
5. autosave ข้ามการปิดเปิดแอป

## 6.1 build ตัวติดตั้งแล้วเจอ EPERM — วิธีที่ใช้ได้จริง

`npm run build` ล้มที่ขั้น electron-builder ด้วย

```
⨯ EPERM: operation not permitted, rename 'release\win-unpacked.tmp' -> 'release\win-unpacked'
```

ไม่ใช่ปัญหาของโค้ด — electron-builder แตกไฟล์ Electron ~200MB ลง `.tmp` แล้ว rename ทันที
แต่มีอะไรจับ handle ของโฟลเดอร์นั้นค้างไว้ตอนนั้นพอดี (ลอง `Rename-Item` เองก็ Access denied
ทั้งที่ `Remove-Item` ผ่าน แปลว่าตัวโฟลเดอร์ถูกจับ ไม่ใช่ไฟล์ข้างใน) เกิดซ้ำได้แม้เปลี่ยน
output dir เป็นโฟลเดอร์ใหม่เอี่ยม

**ทางแก้ที่ใช้ได้:** ชี้ไปที่ Electron ที่แตกไว้แล้วใน `node_modules` แทน ข้ามขั้นดาวน์โหลด
+ แตกไฟล์ + rename ไปเลย เวอร์ชันเดียวกันเป๊ะ (43.4.1) ผลลัพธ์จึงเท่ากัน

```bash
npx electron-builder --win --config.electronDist=node_modules/electron/dist
```

ถ้าจะรันสามขั้นครบเหมือน `npm run build` ให้ทำ `npx tsc -b` กับ `npx vite build` ก่อน

> อย่าไปแตะ Windows Defender หรือตั้ง exclusion เพื่อแก้เรื่องนี้ — เป็นการแก้ค่าความปลอดภัย
> ของเครื่อง ไม่ใช่ของโปรเจกต์ และไม่จำเป็นเพราะมีทางข้ามอยู่แล้ว
